# 知幕 Zhimu Player 可复现部署契约

当前发行版本为 `1.2.0-rc.10` 候选版，并非稳定版，下载见 [GitHub Release](https://github.com/OJY-lawyer/zhimu-player/releases/tag/v1.2.0-rc.10)。
根目录名统一为 `zhimu-player`；下面的命令均在源码根目录执行，不依赖开发者的本机绝对路径。

## 输入与目标

输入为清洁源码包或完整源码仓库，目标是为当前 Windows x64 用户启动播放器，
或生成当前用户安装程序和便携版。用户可以把整个源码包交给 Codex 等 agent，附言：

> 请按 AGENTS.md 部署 知幕 Zhimu Player，复用本机已有 Node，完成依赖、检查和构建，
> 启动首次运行引导。我自己完成账号登录。默认 ChatGPT 网页，由我选择网页模型和推理档位；
> 不要上传个人配置，也不要替我发布仓库。

本契约允许个人、律师和公司员工自行部署，或由其自用 agent 辅助部署，在日常工作中
免费使用。组织内部员工部署、处理工作视频，以及正常工资或专业服务收费不因此被
禁止。第三方对外收费代部署、售卖和商业集成须另获作者书面许可；自愿赞助不授予
商业许可。独立 agent、模型或转写服务的费用不属于本软件许可费。

## 运行条件

| 项目 | 条件 |
|---|---|
| 发行版 | Windows x64；安装包内置 Electron，不要求 Node/Python |
| 源码构建 | Node.js >=22.12；推荐 Node 22 LTS；npm 与锁文件配套 |
| ChatGPT 网页 | 可用的 Microsoft Edge、网络与用户自己的网页账号 |
| DeepSeek API | 网络、用户自己的 API Key 与可用 API 余额 |
| 听悟 | 网络、用户自己的听悟账号、可用服务权限 |

先运行 `node --version` 并检查已有运行时，不自动修改全局 PATH，不使用其他应用的
私有依赖目录。如果运行时不满足条件，说明缺口；只在已有授权内安装项目依赖。
`npm ci` 下载锁定的依赖包；随后 `npm run setup:runtime` 使用 Electron 自带安装器准备
项目内运行文件，可能需要访问 npm 与 GitHub。Electron 44 不再在 npm 安装阶段自动
下载运行文件，因此首次部署须先准备，再执行只读的 doctor 检查。

## 顺序

```sh
npm ci
npm run setup:runtime
npm run doctor
npm run typecheck
npm test
npm run build:app
npm run dev
```

`doctor` 只检查平台、项目文件、依赖版本和浏览器可执行文件是否存在；不读取个人
配置、Cookie、API Key，不打开账号页面。它不能证明登录或服务调用成功。

`npm test` 编译并执行 `scripts/test-*.ts`，排除明确联网的 `test-edge-cdp.ts`。
`npm run test:browser` 才运行浏览器传输测试；它也不能代替真实 ChatGPT 登录验收。
临时测试产物位于 `work/test-run-*`，结束后只清理本次创建的目录。

构建后可运行 `npm run test:desktop`，以隔离的 appData 和合成媒体检查旧版数据兼容。
设置 `ZHIMU_SMOKE_MODE=fresh` 可检查首次使用，默认 `upgrade` 检查旧配置夹具；两种
模式均不使用真实账号或真实云端服务。截图和结果默认放在 `outputs/desktop-verification`。
`ZHIMU_SMOKE_ENTRY` 可指定发行包 ASAR 内的主入口；`npm run verify:package` 检查发行
包的名称、版本、许可与当前构建内容。这些检查不能替代实际安装升级或云端验收。

`npm run test:layout` 在隔离的真实 Electron 窗口中检查长侧栏内容、播放控件位置、
标签切换、窗口与侧栏缩放。它使用合成媒体，不读取用户媒体或登录态，不调用云端。

`npm run test:playback` 以真实 Electron 和无音轨合成视频检查字幕点击、进度条点击/
拖动、切换 Part、音量条及滚轮。加 `-- --slow-media` 模拟媒体尚未读完，核对实际
`currentTime`、`seeked` 和解码就绪，而非仅检查界面显示。`ZHIMU_QA_OUTPUT` 指定证据
目录，`ZHIMU_SMOKE_ENTRY` 可选择候选包的 ASAR 入口，`ZHIMU_TEMP_ARCHIVE` 指定
隔离数据归集位置。测试结束正常关闭窗口，再归集本次隔离目录并记录原路径，不永久删除。
保留有复用价值的脚本和验收证据；不能整包清空混有其他任务材料的 work 或 outputs。

构建发行版执行 `npm run build`；需要先检查解包内容时执行 `npm run build:dir`。
构建会重新生成第三方许可证汇总，并明确禁止自动发布。NSIS 使用当前用户安装，
允许选择目录，并提供简体中文 / English 安装器语言选择；卸载默认保留用户数据。便携版不是账号迁移工具。

候选包命名为 `Zhimu-Player-1.2.0-rc.10-Setup-x64.exe` 和
`Zhimu-Player-1.2.0-rc.10-Portable-x64.exe`；源码导出为
`Zhimu-Player-1.2.0-rc.10-Source.zip`，均从本版 Release 获取。重新构建时应另行检查产物，
不能沿用官方构建的验收结果。检查、打包和导出不授予对外发布权限。

## 更名与升级兼容

知幕 Zhimu Player 延续原 AI Video Player 项目。应用显示名和源码目录更新，内部
`appId` 保持 `com.videoplayer.app`，用户数据目录名保持 `video-player`。保留已有
localStorage 协议键及导读 `ai-video-player-guide:` 标记，避免重置播放状态、界面偏好、
AI 配置或登录态；不要用全局替换改动它们，也不要复制其他应用的登录配置作为迁移。
兼容目标与实际升级验收结果分别记录，不能只凭目录仍存在宣布恢复成功。

许可证仍为同一项目的 1.0 版，仅更新项目显示名称；保留原作者署名及全部授权与限制。
`VALIDATION-*.md` 中旧名时期的记录保留原文，不将历史通过项算作本候选版通过项。

## 账号与首次引导

引导只保留三步：选择导读来源、登录或填写 Key、可选听悟；界面语言在引导及设置中选择简体中文 / English。
用户操作账号密码、验证码和服务授权；agent 可以打开本项目专用登录窗口并检查
返回状态。网页版无需 Codex，模型与推理档位由用户分别选择，不通过 Plus/Pro
推定模型。候选预设尚未验证账号可用性，网页菜单刷新不得自动替换原选择；发送前
必须再次核对。不能从浏览器是否登录推断套餐，也不能把 Codex 额度当作网页或 API 授权。

普通 Edge 人工登录保留，登录阶段不启用自动控制。用户也可主动选用 Cookie-Editor
JSON 文件、剪贴板或当次粘贴的 JSON 导入；主进程只接收 chatgpt.com 及子域条目，限 2 MiB、2000 条，
按域、路径、安全属性和有效期校验，跳过无关/过期/无效条目，不把分区 Cookie 扩大
为普通 Cookie。不要读取日常浏览器数据库、复制整个配置或从其他项目借用凭据。
文件和剪贴板内容不回显；粘贴框在提交、关闭或切换来源后清空，内容不写入配置。
导入后仍要检查连接；不要把导入数量当作认证成功。

认证有 authenticated、signed-out、unknown 三种结果。只有确切证据才判未登录；
网络错误、超时、人机验证、页面未就绪都不能抹掉上次确认记录或清空浏览器资料。
unknown 会阻止尚无法安全确认的生成，并在连接区显示本次检查的具体原因，不要求用户立即重复登录。
遇到 403 或网页安全验证时，保留登录资料，由用户在普通专用窗口完成验证后再检查，不反复导入。

新用户默认普通 ChatGPT 会话，不依赖开发者私有项目名。用户明确设置项目后才核对
项目归属。任何模型缺失、档位不可见或网页变化都应明确失败，不允许静默降级。

API 设置通过 `/models` 自动获取模型名称，不建立固定模型白名单。保留已有选择；
模型未出现在新列表中时提示用户，不自动替换。兼容接口不支持列表时可手动填写。
列表缓存仅在本次运行中保留，按接口和 Key 隔离；认证失败时清除。保存的 Key 仅能
复用于同源接口，列表请求不保存用户尚未保存的草稿 Key，也不发送字幕。

听悟登录由内置 Electron 会话处理，ASR 使用项目内实现；不要恢复旧版 Python/Skill
链，不写死开发者的听悟目录 ID，不从其他软件读取账号。本轮内置转写只保存 SRT，
不承诺额外生成转写 Markdown。

界面语言、导读输出（zh-CN / en / source）和听悟语音（cn / en）互不联动。新用户导读
默认 source，旧配置缺少该字段时保持 zh-CN；新用户听悟初始值参考系统语言。听悟语言须按
媒体实际语音选择，旧配置缺字段时保持 cn。英文转写任务与中文任务分别记录，不将
中文旧任务误作为英文结果复用。已存在有效 SRT 的直接加载规则不因界面语言改变。
英文用户入口见 [README.en.md](../README.en.md)，包括部署命令、登录、语言和故障说明。

新导读使用 Markdown 首部的 `ai-video-player-guide:` HTML 注释保存版本与 Part 文件名
清单（manifest）。显示、搜索及编辑正文时隐藏并保留该记录，按文件名唯一匹配当前
播放列表。排序变化不得改变历史 Part 指向；缺失、更名或匹配歧义只停用受影响链接。
无记录的旧多视频导读无法恢复原顺序，保持阅读和编辑但停用跳转，不按当前顺序猜测。
无记录的单视频导读可以使用唯一视频；记录损坏时一律停用跳转。

## 验收与交付

rc.10 已完成以下验收，详细范围见 [版本说明](./RELEASE-1.2.0-rc.10.md)：

- 25 个离线测试文件、类型检查和构建通过；真实 Electron 限速合成媒体的 19 项播放检查通过。
- 真实 Edge 的 15 项合成 Cookie 协议检查通过；用户完成安全验证后，实际账号多次重启浏览器仍通过认证。
- 实际网页连续切换 Sol Pro → Sol Medium → Astra Pro 均确认成功；用 Sol Medium 完整生成并取回带时间戳的短合成文本导读。回答模型为 `gpt-5-6-thinking`，档位元数据为 `null`，Medium 依据发送前网页核验。
- 发行包首次使用和旧配置升级夹具通过；本机安装程序成功完成覆盖升级，安装归档与构建一致，桌面快捷方式正确。设置、播放记录和 ChatGPT、听悟登录文件共 4 份数据保持不变。

长字幕及附件上传、Pro 或其他未测档位生成、听悟新云端任务、其他机器和 GitHub 增量更新尚未验收。
合成短文本导读不等于真实长视频全流程；不能将历史版本或其他环境的通过项计入本次部署。

分别记录：依赖恢复、离线检查、构建、应用启动、真实界面、真实账号登录、真实云端
任务。只有实际运行的项目才能标记通过。至少用用户允许的一段短视频验证生成 SRT，
再用对应字幕生成导读，并验证保存和点击时间戳跳转。长视频、不同套餐与新机器若未
覆盖，要明确列出边界。不要为验证而批量上传用户媒体。

## 公开源码

```sh
npm run public:check
npm run public:export -- --output outputs
```

导出器仅允许明确列出的根文件、源码、发布文档、测试脚本、工作流、两个图标和作者
明确授权公开的三个关于页图片（微信联系原图、赞助原图及展示海报）和三张介绍截图；拒绝
符号链接和异常大文件。默认不纳入 `work/`、`data/`、`state/`、`outputs/`、历史交接、
本机安装脚本或个人配置。扫描只输出路径、规则名和计数，不输出命中内容。

源码 ZIP 带 `SOURCE-MANIFEST.json`（逐文件 SHA-256）及 ZIP 的 `.sha256` 校验文件；
为避免覆盖已有交付，同名 ZIP 已存在时会失败。公开前仍须人工检查许可、隐私和实际
功能。只有明确获准后才创建仓库、推送或发布，CI 不自动发布发行版。

公开文件必须包含 README.en.md 与 docs/LICENSE.en.md。后者是中文 LICENSE 的忠实
参考译本，不替代中文主文本；保留“欧俊言律师”原文署名和原授权二维码内容。
